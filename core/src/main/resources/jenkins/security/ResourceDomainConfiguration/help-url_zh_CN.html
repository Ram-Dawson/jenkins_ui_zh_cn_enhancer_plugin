Jenkins 会提供许多可能由不受信任用户创建的文件，例如项目工作区中的文件或已归档的构建产物。 当未定义资源根 URL 时，Jenkins 会在返回这些文件时附带 Content-Security-Policy （“CSP”）HTTP 响应头。 默认情况下，它会被设置为一个较严格的值，以禁用许多现代 Web 功能，从而防止访问这些文件的 Jenkins 用户遭受跨站脚本（XSS）等攻击。 虽然 CSP 响应头的具体值可以由用户自行配置，甚至可以完全关闭，但这本质上是在安全性与功能性之间做取舍。

如果定义了资源根 URL，Jenkins 会将用户创建资源文件的请求重定向到以此处配置 URL 开头的地址。 这些地址不会设置 CSP 响应头，因此 JavaScript 等功能也可以正常工作。 若要让此选项按预期生效，需要满足以下约束和注意事项：

  • 资源根 URL 必须是 Jenkins URL 的一个有效替代入口，否则请求将无法被正确处理。
  • 必须先设置 Jenkins URL，并且它必须与该资源根 URL 不同（实际上要求使用不同的主机名）。
  • 一旦启用，Jenkins 只会通过资源根 URL 来提供资源 URL 请求；所有其他请求都会得到 HTTP 404 Not Found 响应。

当此 URL 被正确设置后，Jenkins 会把对工作区、已归档构建产物以及其他通常由用户生成内容集合的请求，重定向到以资源根 URL 开头的地址。 这些资源 URL 不再是像 job/name_here/ws 这样的路径，而会包含一个编码令牌，其中记录了原始路径、为哪个用户创建以及创建时间。 这些资源 URL 访问静态文件时，会 视同 为创建该 URL 的那个用户正在访问这些文件： 如果该用户后来失去了访问这些文件的权限，对应的资源 URL 也同样会失效。 在这些 URL 过期之前，任何人都可以在无需认证的情况下访问它们，因此分享这些 URL，几乎就等同于直接分享这些文件本身。

安全注意事项

认证

资源 URL 不需要认证（用户在资源根 URL 下不会拥有有效会话）。 因此，将资源 URL 分享给其他用户时，即便对方没有 Jenkins 的 Overall/Read 权限，也依然可以在这些 URL 过期之前访问对应文件。

过期

默认情况下，资源 URL 会在 30 分钟后过期。 过期后的资源 URL 会把用户重定向到对应的 Jenkins 原始 URL，这样用户就可以在必要时重新认证，然后再被重定向回一个新的资源 URL，该新 URL 又会再有效 30 分钟。 如果用户本身已有有效的 Jenkins 会话，这一过程通常对其是透明的；否则，他们需要重新登录 Jenkins。 不过，在浏览带有 HTML frame 的页面（例如 Javadoc 站点）时，登录表单无法直接显示在 frame 中。 在这种情况下，用户需要刷新顶层 frame，登录表单才能出现。

如需修改资源 URL 的过期时长，可将系统属性 jenkins.security.ResourceDomainRootAction.validForMinutes 设置为所需的分钟数。 过期时间越短，资源 URL 的使用便利性会下降；过期时间越长，则被授权用户分享出去的 URL 被未授权用户利用的风险也会相应增加。

真实性

资源 URL 会对其原始 URL、创建该 URL 的用户以及创建时间戳进行编码。 此外，这段字符串中还包含一个 HMAC ，用于确保 URL 的真实性。 这可以防止攻击者伪造 URL，从而冒充其他用户访问资源文件。
