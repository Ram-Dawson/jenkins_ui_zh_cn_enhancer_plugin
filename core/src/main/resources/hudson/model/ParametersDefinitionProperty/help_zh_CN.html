参数可以让你在启动构建时提示用户输入一个或多个值，并把这些值传递到构建过程中。 例如，你可能有一个项目用于按需执行测试，允许用户上传一个包含待测二进制文件的 zip 包； 这时就可以在这里添加一个 文件参数 。
又或者，你有一个用于发布软件的项目，希望用户输入发布说明并与软件一起上传； 这时可以在这里添加一个 多行字符串参数 。

每个参数都有一个 名称 ，以及根据参数类型而定的某种 值 。 当构建开始时，这些名称和值会被导出为环境变量，以便后续构建配置中的其他部分（例如构建步骤）访问这些值， 比如通过 ${PARAMETER_NAME} 语法（在 Windows 上则是 %PARAMETER_NAME% ）。
这也意味着这里定义的每个参数都应该使用唯一的 名称 。

当一个项目被参数化后，原本的 立即构建 链接会变成 使用参数构建 ，用户需要先为每个参数指定值再启动构建。 如果用户什么都不填，构建会使用每个参数的默认值启动。

如果构建是自动触发的，例如由 SCM 触发器启动，那么会使用每个参数的默认值。

当参数化构建已经在队列中时，如果你再次尝试为同一个项目启动构建，只有在参数值不同， 或者启用了 必要时允许并发构建 选项的情况下，这次启动才会成功。

更多信息请参阅 参数化构建文档 。
