这里定义一个逻辑表达式，用来决定哪些代理节点可以执行此项目的构建。 将该表达式与每个可用代理节点的名称和标签进行匹配后，结果只会是 true 或 false 。 如果表达式计算结果为 true ，该代理节点就允许执行此项目的构建。

如果此项目应始终在某个特定代理节点上构建，或者始终在内置节点上构建，你可以直接填写该代理节点的名称，或者分别填写 built-in 。

不过，通常应尽量避免在这里直接使用代理节点的 名称 ，而应优先使用代理节点的 标签 。 正如每个代理节点的配置页面以及控制器的 系统配置 页面中所说明的，标签可以用来表示代理节点所运行的操作系统、CPU 架构，或其他任意特征。
使用标签的好处是：每当你新增、删除或重命名代理节点时，无需反复修改这里填写的标签表达式。

标签表达式既可以非常简单，只写一个 标签 或 代理节点名称 ，例如 android-builder 或 linux-machine-42 ；
也可以结合多种 运算符 组成更复杂的表达式。

支持的运算符

以下运算符按优先级从高到低排序：
(expression)
括号，用于显式指定表达式的结合方式
!expression
NOT，表示取反； expression 的结果必须 不 为真
a && b
AND，表示“并且”； a 和 b 两个表达式都必须为真
a || b
OR，表示“或者”； a 或 b 任一表达式为真即可
a -> b
“蕴含”运算符，等价于 !a || b 。
例如， windows -> x64 可以理解为：“如果使用的是 Windows 代理节点，那么它 必须 是 64 位”； 但同时仍允许此项目在那些 没有 windows 标签的代理节点上运行，而不管它们是否还带有 x64 标签。
a <-> b
“当且仅当”运算符，等价于 a && b || !a && !b 。
例如， windows <-> dc2 可以理解为：“如果使用的是 Windows 代理节点，那么它 必须 位于数据中心 2；而如果使用的不是 Windows 代理节点，那么它 就不能 位于数据中心 2。”

说明

  • 所有运算符都是左结合的，也就是说， a -> b -> c 等价于 (a -> b) -> c 。
  • 如果标签或代理节点名称中包含会与运算符语法冲突的字符，可以用引号包起来。
    例如： "osx (10.11)" || "Windows Server" 。
  • 表达式中可以不写空白字符，但为了便于阅读，建议保留空格；Jenkins 在计算表达式时会忽略这些空白。
  • 不支持通过通配符或正则表达式来匹配标签或代理节点名称。
  • 空表达式始终会计算为 true ，即匹配所有代理节点。

示例

built-in
此项目的构建只能在内置节点上执行
linux-machine-42
此项目的构建只能在名称为 linux-machine-42 的代理节点上执行（或者执行在任何恰好带有 linux-machine-42 这个标签的机器上）
windows && jdk9
此项目的构建只能在安装了 Java Development Kit 9 的 Windows 代理节点上执行（前提是安装了 JDK 9 的代理节点都被打上了 jdk9 标签）
postgres && !vm && (linux || freebsd)
此项目的构建只能在 Linux 或 FreeBSD 代理节点上执行，并且这些节点 不能 是虚拟机，同时还必须安装了 PostgreSQL（前提是每个代理节点都已正确打上对应标签，尤其是运行在虚拟机中的代理节点必须带有 vm 标签，此示例才会按预期工作）
