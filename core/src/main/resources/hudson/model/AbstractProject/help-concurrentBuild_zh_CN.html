勾选这个选项后，该项目的多个构建可以并行执行。

默认情况下，同一个项目一次只会执行一个构建，其他对该项目的构建请求会一直留在构建队列中，直到前一个构建完成。
这是一个更安全的默认值，因为项目通常可能需要独占某些资源，例如数据库或特定硬件设备。

但如果启用了这个选项，并且当前有足够的构建执行器可以处理该项目，那么该项目的多个构建就会并行执行。 如果某个时刻可用执行器不足，后续构建请求仍会像平常一样进入队列等待。

对于执行长时间测试套件的项目来说，启用并发构建会很有帮助，因为它可以让每次构建包含更少的变更， 同时由于后续构建不必等待前一次测试完成，总体周转时间也会缩短。
这个功能对参数化项目也很有用，因为不同参数组合下的各次构建执行通常可以彼此完全独立。

每个并发执行的构建都会在各自独立的工作区中运行，与其他构建隔离。 默认情况下，Jenkins 会在工作区目录名后追加 @<num> ，例如 @2 。
这个 @ 分隔符可以在启动 Jenkins 时通过设置 hudson.slaves.WorkspaceList Java 系统属性来修改。 例如， hudson.slaves.WorkspaceList=- 就会把分隔符改成连字符。
更多关于设置系统属性的信息，请参见 官方文档 。

但是，如果你启用了 使用自定义工作区 选项，那么所有构建都会在同一个工作区中执行。 这时就需要格外小心，因为多个构建可能会同时修改同一个目录。
