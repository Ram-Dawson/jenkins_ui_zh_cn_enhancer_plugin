如果您想跟踪仓库中的特定分支，请指定分支。 如果留空，将检查所有分支是否有更改并构建。

最安全的方法是使用 refs/heads/<branchName> 语法。这样预期的分支 是明确的。

如果您的分支名称中包含 /，请确保使用上面的完整参考。未呈现时 如果使用完整路径，插件将仅使用最后一个斜杠右侧的字符串部分。 含义 foo/bar 实际上会匹配 bar.

如果您使用带有斜线的通配符分支说明符（例如 release/）， 您需要在分支名称中指定原始仓库 确保更改被采纳。所以例如origin/release/

可能的选项：

  • <branchName>
    跟踪/检出指定的分支。如果不明确，则采用第一个结果，这不一定是 预期的一个。最好使用 refs/heads/<branchName>。
    例如master, feature1, ...
  • refs/heads/<branchName>
    跟踪/检查指定分支。
    例如refs/heads/master, refs/heads/feature1/master, ...
  • <remoteRepoName>/<branchName>
    跟踪/检出指定的分支。如果不明确，则采用第一个结果，这不一定是 预期的一个。
    最好使用 refs/heads/<branchName>。
    例如origin/master
  • remotes/<remoteRepoName>/<branchName>
    跟踪/检查指定分支。
    例如remotes/origin/master
  • refs/remotes/<remoteRepoName>/<branchName>
    跟踪/检查指定分支。
    例如refs/remotes/origin/master
  • <tagName>
    这不起作用，因为标签不会被识别为标签。
    请改用 refs/tags/<tagName>。
    例如git-2.3.0
  • refs/tags/<tagName>
    跟踪/检查指定标签。
    例如refs/tags/git-2.3.0
  • <commitId>
    检查指定的提交。
    例如5062ac843f2b947733e6a3b105977056821bd352, 5062ac84, ...
  • ${ENV_VARIABLE}
    也可以使用环境变量。在这种情况下，变量被评估并且 结果的使用如上所述。
    例如${TREEISH}, refs/tags/${TAGNAME}, ...
  • <Wildcards>
    语法格式为：REPOSITORYNAME/BRANCH。 另外，BRANCH被识别为*/BRANCH的简写，'*'被识别为通配符， '**' 被识别为包含分隔符 '/' 的通配符。因此，origin/branches* 会 匹配 origin/branches-foo 但不匹配 origin/branches/foo，而 origin/branches** 会 匹配 origin/branches-foo 和 origin/branches/foo。
  • :<regular expression>
    语法格式为：:regexp。 要构建的分支中的正则表达式语法将仅 构建那些名称与常规名称匹配的分支 表达式。
    示例：
    • :^(?!(origin/prefix)).*
      • 匹配：origin或origin/master或origin/feature
      • 不匹配：origin/prefix或origin/prefix_123或origin/prefix-abc
    • :origin/release-\d{8}
      • 匹配：origin/release-20150101
      • 不匹配：origin/release-2015010或origin/release-201501011或origin/release-20150101-something
    • :^(?!origin/master$|origin/develop$).*
      • 匹配：origin/branch1或origin/branch-2或origin/master123或origin/develop-123
      • 不匹配：origin/master 或 origin/develop
