quietPeriod 选项允许为该项目指定 quiet period。

当该选项非 0 时，新触发的构建会先进入队列，但 Jenkins 会在真正开始构建前等待指定的时间（秒）。

例如，如果构建执行时间较长，你可能希望避免在短时间内连续提交源码时触发多个构建。启用 quiet period 后，Jenkins 发现第一次提交时不会立刻启动构建，这样开发者还有机会继续推送更多提交，等构建真正开始时会一并包含进去。这可以减少队列中的任务数量，让开发者更快获得这一组提交的反馈，也能降低 Jenkins 系统负载。

如果在已有构建正在队列中等待其 quiet period 结束时，又触发了该项目的新构建，那么 quiet period 不会被重置。新触发的构建也不会再次入队；但如果该项目是参数化任务，且这次构建的参数与队列中已有构建不同，则仍会单独入队。
